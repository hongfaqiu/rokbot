What’s new · 2026-11-28

11 月 28 日：Bot 详情页、设置分组导航、更懂你的输入建议Nov 28: Bot details, grouped settings and suggestions that learn

输入建议按 Bot 学习你的习惯并在本地即时补全；桌面端与网页版新增 Bot 详情页和分组导航的设置页；搜索结果带匹配度与覆盖率；自动审核按官方 schema 整份校验。桌面与网页 1.3.5，安卓 1.26.0-rokbot.15，通过自建 Host 的「更新」通道获取，无需重新配对。 Suggestions learn your habits per Bot and complete locally as you type; desktop and web gain a Bot details page and grouped settings navigation; search results carry relevance and coverage; auto-review validates the full official schema. Desktop and web 1.3.5, Android 1.26.0-rokbot.15, delivered through your own Host’s update channel with no re-pairing.

Suggestions

输入建议按 Bot 学习你的习惯Suggestions learn your habits, per Bot

不再出现与当前 Bot 无关的通用填充建议；输入时在本地即时补全，不必等待网络请求；建议条淡入、上浮，切换更顺滑。设置中可关闭「学习输入习惯」并一键清除学习记录。覆盖 Android、桌面端和网页版。No more generic filler unrelated to the current Bot; completions appear locally as you type without waiting on the network, and the suggestion bar fades and slides in. Turn off learning in Settings and clear what was learned in one tap. On Android, desktop and web.

Bot details

Bot 详情页，一页看全Bot details on one page

桌面端与网页版新增 Bot 详情页：人设、模型与工具、自动化、记忆与用量集中在一页；与 Bot 资料库共用同一份数据，改动后各处一致。Desktop and web get a Bot details page: persona, models and tools, automations, memory and usage in one place. It shares data with the Bot library, so edits show up everywhere.

Settings

设置页分组导航Grouped settings navigation

桌面端与网页版左侧分组、右侧内容，长设置页不再一直往下滚；在输入建议列表上滚动会正常滚动页面。「数据迁移」位于第一级，Android、桌面端和网页版都能直接找到。Desktop and web show groups on the left and content on the right, so long settings no longer scroll forever, and scrolling over the suggestion list scrolls the page. Data migration sits at the top level on Android, desktop and web.

Search

搜索带匹配度与覆盖率Search with relevance and coverage

Host 的 Bot 与媒体搜索统一返回匹配项和覆盖率，界面据此提示「结果不完整」或继续加载；Android 搜索不再显示为不可用。索引缺失或损坏时自动重建。The Host’s Bot and media search always return matches plus coverage, so clients can flag incomplete results or load more, and Android search no longer shows as unavailable. A missing or damaged index rebuilds itself.

Auto-review

自动审核整份校验Auto-review checks the whole verdict

判定结果按官方 schema 整份校验；放行时允许空的操作说明，不再被误判为格式错误。校验不过仍重试一次，再失败才回落到手动确认。Verdicts are validated against the full official schema; an allow with an empty action description is accepted instead of being treated as malformed. A failed check still retries once before falling back to manual approval.

      Quick Start

      三步部署你的私有 HostDeploy your private Host in three steps

      准备一台装好 Docker（含 Compose v2）的 Linux 或 macOS 服务器（建议 4 核 8 GB）。也可以直接把 AI 部署手册 发给编程助手自动完成。 Requires any Linux or macOS machine with Docker & Compose v2 (4C8G recommended), or hand the AI agent deployment guide to your coding assistant.

      1. 01

        启动 Host 与云电脑容器Launch Host & box

        克隆仓库并在本地运行安装脚本（自动生成 0600 权限的 .env 随机密钥并启动 host 与 box）。支持 --offline 离线导入及 源码构建。 Clone the repo and run the installer with --local to generate .env (mode 0600) with random secrets and start host & box. Supports --offline and source builds. 

        gh repo clone hongfaqiu/rokbot rokbot-src
mkdir rokbot && cd rokbot
bash ../rokbot-src/host/release/install-images.sh --local
      2. 02

        初始化管理密码与配对Initialize & pair

        读取一次性初始化密钥，打开管理页 http://127.0.0.1:18080/admin 设置管理员密码（12–128 位），并在「设备与通知」生成 6 位配对码连接客户端。 Read the one-time setup key, open http://127.0.0.1:18080/admin to set your admin password (12–128 chars), and generate a 6-digit pairing code for your clients. 

        docker compose --env-file .env -f docker-compose.images.yml exec -T host cat /data/setup-key
      3. 03

        配置自选模型与备用链Configure models

        在管理页「对话模型」（/admin?view=model）添加 OpenAI Chat、OpenAI Responses 或 Anthropic 服务商与 API Key，拉取模型列表、测试连接并设定主/备路由，即可创建 Bot 开始工作。 Open Chat Models (/admin?view=model), add your OpenAI Chat, OpenAI Responses, or Anthropic provider & API key, test the connection, set your primary and fallback chain, and create your first Bot.

      发布渠道与下载说明Release channels & downloads

      安装包只从你自己的 Host 分发。发布一次，已配对的设备都会收到更新。 Installers are distributed only from your own Host. Publish once and every paired device gets the update.

      1. 服务端：本地源码构建镜像Server: build images locally from source

        使用项目构建脚本 host/release/build-docker.py 从源码在本地构建 host（amd64 / arm64）与 box（amd64）镜像；已有镜像也可离线导入。仓库与本站均不提供现成镜像。Build the host (amd64 / arm64) and box (amd64) images locally from source with the project build script host/release/build-docker.py, or import them offline if you already have them. Neither the repository nor this site provides ready-made images.

        build-docker

      2. 客户端：从你的 Host 下载与自动更新Clients: download & auto-update from your Host

Android upgrades in place when the release certificate matches; iOS uses itms-services or AltStore / SideStore feeds.

        /admin · updates

        node · python3

      01使用补丁工具自行构建Build yourself with patch tools

      02从你自己部署的 Host 获取Get from your own deployed Host

      Host 管理员可以把自行构建并签名的客户端上传到自己的服务器，直接向已配对设备分发和推送增量更新： Host administrators can upload self-built, signed client packages to their own Host and distribute delta updates directly to paired devices:

      1. 管理员按左侧步骤构建并签名对应平台的客户端包。Build and sign the client packages locally using the patch tools.
      2. 在管理页「客户端更新」上传并发布，支持基于旧版本生成增量差分补丁。Upload in Admin → Client updates and optionally generate delta patches from an older build.
      3. 已配对的 Android 与桌面客户端（macOS、Windows、Linux 1.3.5）自动从你的 Host 校验（SHA-256 / ECDSA P-256 / 证书一致）并升级；iOS 支持 itms-services 与 AltStore / SideStore 源。Paired Android & desktop clients (macOS, Windows, Linux 1.3.5) verify SHA-256 / ECDSA P-256 / certs and update directly; iOS supports itms-services and AltStore / SideStore feeds.

      FAQ & Compliance

      常见问题与合规说明FAQ, License & Compliance

      没有公网 IP，如何在外面连接自己的 Host？How do I connect remotely without a public IP?

      在管理页「远程访问」开启内置的 Tailcat 加密组网（无需 Tailscale 账号），也可使用 Tailscale、VPN 或 HTTPS 反向代理。请勿将管理页端口直接裸露公网，详见 SECURITY.md。Enable built-in Tailcat encrypted networking under Remote access (no Tailscale account required), or use Tailscale, VPN, or an HTTPS reverse proxy. Never expose the admin port directly to the public internet; see SECURITY.md.

      API Key 存在哪里？会被读出来吗？Where are API keys stored?

      全部保存在你自有服务器 Host 数据卷的 /data/model.env 中，采用只写不读策略。管理接口与各客户端只能看到「是否已设置」，永远不会回显明文 Key。All keys are stored write-only inside your Host volume at /data/model.env. Neither the admin API nor any client can read plaintext keys back.

      ARM 服务器可以部署吗？Can I deploy on an ARM server?

      可以。Host 镜像原生支持 linux/amd64 与 linux/arm64；执行桌面 box 目前仅提供 linux/amd64 镜像，ARM 宿主机开启 binfmt/QEMU 或 Apple Silicon Rosetta 即可运行，或将 box 独立部署在 x86 节点上。Yes. Host supports both linux/amd64 and linux/arm64. The box desktop image is linux/amd64 (runs via binfmt/QEMU or Rosetta, or deploy box on a separate x86 node).

      上传文件有大小限制吗？Is there a file size limit?

      默认没有。电脑与 Bot 工作区之间的复制已改为分块流式传输；如需限制，在 Host 设置环境变量 ROKBOT_MAX_TRANSFER_BYTES。Not by default. Copies between your computer and the Bot workspace stream in chunks; set ROKBOT_MAX_TRANSFER_BYTES on the Host to impose a cap.

      Android 升级会丢数据吗？Will an Android upgrade wipe my data?

      不会。正式版统一使用 RokBot 签名证书，1.26.0-rokbot.15 可直接覆盖上一版安装；证书不一致的包在构建阶段就会被拦下。No. Release builds share the RokBot signing certificate, so 1.26.0-rokbot.15 installs over the previous version; mismatched builds are rejected at build time.

      怎么备份与迁移数据？How do I back up and restore data?

      数据位于 host-data、box-home 与 box-workspace 三个 Docker 数据卷中，可使用 python3 host/deploy.py backup 打包备份。切勿运行 docker compose down -v，否则会清空数据卷。All state lives in host-data, box-home, and box-workspace Docker volumes. Run python3 host/deploy.py backup to archive them, and avoid docker compose down -v.
